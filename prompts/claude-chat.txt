Good news: this is very doable. I dug into Eagle's plugin API docs (they're public and current) to check feasibility before promising anything, and here's what I found relevant to your step 5:

What's confirmed possible:

    eagle.item.get({ folders: [folderId] }) — pulls every item in a folder, each with its .tags array.
    eagle.folder.getSelected() — gets whatever folder you currently have open/selected in the app.
    eagle.item.addFromPath(path, { name, tags, folders }) — lets the plugin create a new item (your tag-sink file) from a file on disk if one doesn't already exist in the folder.
    Item and folder objects have a .save() method to persist tag changes.

One real constraint: I checked Eagle's event API (the full list of things a plugin can be notified about: plugin created/run/shown/hidden, library switched, theme changed), and there is no "a tag was added to an item" event. Eagle plugins run in their own separate window rather than injecting into the main app's UI, so there's no way to silently watch you tagging files in the main Eagle window and react instantly. That means the "reactive, as I'm adding tags" version of step 5 isn't achievable with the public API — only the "press a button" version is. You mentioned both as options, so this isn't a dealbreaker, just confirming which path we're on.

Given that, a few design decisions will shape the code, so let me ask before writing anything:
How should the plugin decide which file in a folder is the "tag-sink"?
Whichever file I manually mark somehow (e.g. via a special tag like 'is-sink')
When you press the sync button, should the tag-sink's tags be REPLACED with the current union of all other files' tags, or should new tags only ever be ADDED (never removed, even if a source file loses a tag)?
Replace (exact mirror of current state)
If no image/file exists yet to serve as tag-sink, what should the plugin auto-create?
A tiny blank image file (so it looks/behaves like your avatar images)
Updated memory
