I teach statistics, and I find a lot of datasets that I use for teaching, creating problems/assignments, etc. Even if "the dataset" is one simple CSV file, there are often many files associated with that dataset such as a journal article, a news article, images, assignments I've made based on the dataset, etc. What I really want is a good way of organizing these datasets that includes tags, searchable text, etc. and - this is important - when I search among the datasets I've found, I want the entire collection of files I have for an associated dataset to be the result. For example, some datasets include multiple data files with one data file being information about participants (e.g., demographic information), and another file that contains measurements about the participants at several time points; the information would be linked by participant ID in the analysis. I might have tags A, B, and C for the participant file and C, D, and E for the measurements file because they have different pedagogical uses. These tags can also be for different licenses, because often the data, journal article, supplemental files, etc. are all released under different licenses.

I think I've found a good category of software that might suit my needs: Digital Asset Management software used by designers/creators to catalogue and retrieve assets, but these tend to lack the bundling features I need. I've spent a lot of time looking at the Eagle app (Eagle.cool) and I think it almost has what I want, but not quite. It does, however, have a Javascript plugin API with public documentation, so I think the features that I want can be added to the software. 

What I want is a plugin for Eagle that will allow me to have the following workflow when managing a dataset: 
1) Create a new folder to store the files in.
2) Add the files to the folder.
3) Apply tags and other metadata to some/all of the files. 
4) [Optional] Add an image to the folder to serve as a kind of avatar or context reminder. (I used these in my slides, for example, by placing this image in the corner so that slides across many presentations that use the same dataset have some clear connection. This image is usually one I find online with some free license, but I don't always include an image. I can give this a standardized name, but don't usually at this point.)
5) Either when I press a button or actively as I'm adding tags, I want every single tag that I use on any file in the folder to be applied to a new file (perhaps called "tag-sink" or something similar). If I create this file - such as by adding an image and naming it "tag-sink.png" or similar - I want this file to be the one to receive all the tags. If I don't supply an image, then a generic file would be fine.

Claude diagnosed this error: 

Bug #1 — the launch error. You're right that it's timing, not packaging. Eagle fires plugin-show on the very first launch in addition to plugin-create, and they can race — your window's onPluginShow handler (which calls folder.getSelected()) can fire before Eagle has finished wiring up the internals that onPluginCreate unlocks. Since you only saw it at launch and everything else worked, that's exactly this race, not a packaging problem. Fix: make every handler that touches the Eagle API wait on a "ready" signal that only resolves once onPluginCreate has actually finished.

But I used up my credits before the fix could be implemented. Please update plugin.js to address this error.

Yes. I updated plugin.js to address the startup race Claude identified.

The key change is a pluginReady promise:

    plugin-create performs the initial Eagle API call directly.

    It resolves pluginReady only after initialization/initial refresh has completed.

    plugin-show now waits for pluginReady before calling refreshFolder().

    The Sync action also waits for readiness.

    If the initial refresh itself fails, the readiness promise is still resolved, so the plugin won't hang indefinitely.

I left your existing Tag Sink behavior unchanged.
