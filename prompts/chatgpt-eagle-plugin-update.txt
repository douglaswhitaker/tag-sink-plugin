I teach statistics, and I find a lot of datasets that I use for teaching, creating problems/assignments, etc. Even if "the dataset" is one simple CSV file, there are often many files associated with that dataset such as a journal article, a news article, images, assignments I've made based on the dataset, etc. What I really want is a good way of organizing these datasets that includes tags, searchable text, etc. and - this is important - when I search among the datasets I've found, I want the entire collection of files I have for an associated dataset to be the result. For example, some datasets include multiple data files with one data file being information about participants (e.g., demographic information), and another file that contains measurements about the participants at several time points; the information would be linked by participant ID in the analysis. I might have tags A, B, and C for the participant file and C, D, and E for the measurements file because they have different pedagogical uses. These tags can also be for different licenses, because often the data, journal article, supplemental files, etc. are all released under different licenses.

I think I've found a good category of software that might suit my needs: Digital Asset Management software used by designers/creators to catalogue and retrieve assets, but these tend to lack the bundling features I need. I've spent a lot of time looking at the Eagle app (Eagle.cool) and I think it almost has what I want, but not quite. It does, however, have a Javascript plugin API with public documentation, so I think the features that I want can be added to the software.

1) Create a new folder to store the files in.
2) Add the files to the folder.
3) Apply tags and other metadata to some/all of the files. 
4) [Optional] Add an image to the folder to serve as a kind of avatar or context reminder. (I used these in my slides, for example, by placing this image in the corner so that slides across many presentations that use the same dataset have some clear connection. What changed in 1.2.0

    Added a separate “Add File Types to Tag-Sink” button.

    It examines every non-tag-sink item in the currently selected Eagle folder.

    It uses Eagle's item.ext property to obtain the file extension. Eagle's current API explicitly exposes ext as a read-only item property.

    Each distinct extension becomes a tag on the tag-sink. For example, a folder containing:

        data.csv

        measurements.xlsx

        article.pdf

        figure.png

    will add the tags csv, xlsx, pdf, and png.

    Existing tags on the sink are preserved; this operation is additive, unlike the normal tag synchronization, which replaces the sink's non-marker tags.

    The file-type operation is deliberately a separate button, rather than changing the existing Sync behavior.

    It gives an Eagle notification describing what was added.

    I also cleaned up a duplicate refreshFolder() definition that was present in the supplied plugin code.

The existing marker-tag mechanism remains unchanged; the supplied UI identifies the marker tag as the mechanism for selecting the tag-sink. The manifest remains based on your 1.1.0 plugin, with the version bumped to 1.2.0.

No. I did not use an external image-generation library in 1.3.5.

The thumbnail generation is done directly by the plugin code. In particular, it generates the thumbnail data itself and then gives that image to Eagle. Eagle's Plugin API explicitly supports adding an image from Base64 via eagle.item.addFromBase64(), so there is no need for an image-processing package just to create these simple labelled thumbnails.

Eagle's plugin environment does allow third-party modules, so using something like a PNG-generation library would be possible in principle. But 1.3.5 doesn't depend on one, which is preferable here:

    no additional dependency to maintain;

    no third-party license to worry about;

    no external service or network connection;

    the plugin remains self-contained.

One clarification, though: I should have been more explicit about what 1.3.5 actually generates. It uses a self-contained image representation rather than invoking ChatGPT's image-generation system or any external AI image generator. There is therefore no question of an image-generation service's terms or license being incorporated into your Eagle plugin.

If we later decide that the thumbnails need more sophisticated typography or graphics, we could consider adding a library, but for these simple folder-label thumbnails I'd strongly prefer keeping the current dependency-free approach.
